# 需求范围与非目标

## 产品目标

独立教师工作台服务于一名大学生家教老师，建立“学生与课程 → 教案草稿 → 授课 → 反馈审核 → 正式进度与掌握度 → 下次建议与练习”的闭环，同时管理课时和收款。

## 必须保持的产品原则

- 一个学生可以关联多个学科，但计划、进度、知识点掌握和收费课程必须按 `StudentSubject` 隔离。
- AI 只产生草稿或建议。教师批准前不得覆盖正式反馈、教学计划或掌握度。
- 教案、反馈、练习和提示词保留不可变版本；失败任务不得破坏已有版本。
- 课程调课、计划调整、应收覆盖和重要删除必须可追溯。
- 仪表盘数据来自正式结构化记录，不从自然语言反馈临时推断。
- 所有页面除登录和健康检查外都必须经过认证。

## Phase 0 范围

- 可安装、可启动的 Web/API/Worker/PostgreSQL 工程骨架。
- 初始安全与任务表迁移、健康检查、Mock Worker 测试。
- 架构、ER、状态、安全、参考项目和路线图文档。
- 本地与 CI 的 lint、类型检查、单元测试、构建及迁移检查。

## 非目标

- 学生端、家长端、多教师、机构层级、课程商城、在线支付。
- Phase 0 不提供业务 CRUD、课程日历、真实 AI 调用、OCR、DOCX 导出或收费报表。
- 不建立 Redis、全文向量数据库、微服务集群或 Kubernetes。
- 不复制参考项目的代码、素材或提示词正文。
- MVP 公式导出按可读文本处理，不承诺 Word 原生公式编辑器对象。
