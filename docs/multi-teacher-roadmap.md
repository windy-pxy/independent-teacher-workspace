# 多独立教师改造路线与验收门

用户已授权分阶段实施。本文作为后续开发依据，不代表所有阶段已经完成。

## 产品目标

独立教师自行注册、登录，在自己的数据空间管理教学资料。同一账户在不同电脑登录后能读取服务器中已经保存的记录；退出登录只撤销会话。当前个人账户与业务资料完整保留。

不扩展机构共享、学生端、家长端及订阅收费。公网部署完成前，其他电脑跨网络访问仍不可用。

## 现有实现审查

- `models.py` 中 `uq_users_single_active` 明确禁止同时存在两个启用账户；CLI 同样限制单账户。现有隔离测试通过停用前一用户再创建下一用户验证，不能当作同时多教师的证据。
- 密码已经由 pwdlib 使用 Argon2 保存，不需要把既有密码转换成可逆加密；新注册沿用 Argon2id 并测试存储格式。
- Student、Subject、UploadedMaterial、PromptTemplate 和 AIJob 已有教师所有权；计划、课程、教案等通过关联学生访问。需要逐接口检查关联操作，不只检查列表。
- 浏览器共用 QueryClient，业务查询键未包含教师标识。登录/退出边界原来未清理缓存，可能造成上一账户信息短暂显示。
- 登录限制位于单进程内存，服务重启会重置；尚不足以承担公开注册、找回密码的防滥用边界。
- AI Provider 和密钥是部署级设置；新教师不可不受限地消耗现有付费额度。
- 默认 Compose 为本机监听；生产覆盖支持云服务器，但尚无本次可用的云服务器和域名。

## 架构决策

本轮每位教师只有一个私人空间，继续以服务端会话 User.id 作为唯一所有权依据。暂不增加 WorkspaceMember 或把全部业务表复制一套 workspace_id；现有归属链可避免大规模迁移及双重事实源。未来引入团队共享或一人多空间时，再设计 Workspace 迁移。

PostgreSQL 为唯一正式事实源，上传文件使用持久卷/StorageProvider；浏览器缓存仅为显示加速。清除缓存不能删除服务端记录。

## 分阶段实施

### M1：改造基础与会话隔离（代码与限定范围验证已完成）

- 把首次使用者验收要求写入 AGENTS.md。
- 检查单账户限制、会话、教师归属和部署现状。
- 登录成功及退出时取消旧查询并清理缓存；退出后完整加载登录页，释放页面内存状态。
- 显示退出进行中/失败反馈；失败时允许用户重试。
- 增加迟到请求、账户切换缓存与退出后重新登录仍能读取记录的测试。
- 不修改账户限制或对外开放注册。

### M2：注册和账户安全（开发与限定范围验收完成，2026-09-11）

- 添加受配置控制的真实注册入口、输入校验、密码确认及清晰结果反馈。
- Alembic 迁移移除单启用账户限制；保持既有 User ID 和资料不变。
- 注册事务处理重复账户和并发；确定用户名规范化及既有账户兼容策略。
- 持久化注册/登录限流，避免只靠进程内存；反向代理来源身份必须可验证。
- 密码修改、会话撤销、找回凭据的单次使用。当前选择离线恢复码：仅展示一次、只保存哈希、使用后失效、可验证密码后轮换；它是长期备用凭据，不是短时邮件链接。无邮件服务时不做虚假的邮件找回入口。未来改用邮件时另行实现短时过期令牌与送达验收。
- 公网注册默认关闭，M3/M4 验收后再开放。测试默认 Mock，不使用现有付费密钥。
- 实际验证与限制见 `m2-account-verification.md`；公开多教师运行不在本阶段完成声明中。

### M3：全业务隔离与跨会话持久化

- 在真实 PostgreSQL 测试库同时注册两名虚构教师。
- 覆盖学生、学科、关联、计划、课程、教案、反馈、错题、练习、收款、模板、文件、AIJob 和导出。
- 尝试替换 URL/请求体 ID、跨教师关联、下载及更新；必须拒绝并保持原记录不变。
- 真实浏览器分别注册和登录，保存后退出、新会话重新登录和测试服务重启后验证记录仍在。
- 检查同浏览器换账户、浏览器后退、多个标签页切换及迟到请求；加固缓存与页面状态边界。
- 保存失败及未保存离开提醒、多设备并发修改冲突可见。

### M4：公网运行前准备

- 决定 AI 费用归属；先以受限平台额度或 Mock 验证，未经选择不建立无限制付费调用。
- 接入实际邮件服务（若采用邮箱注册/找回），处理注册滥用、配额和账户停用。
- 整理用户隐私告知、数据导出与删除路径，明确 AI 数据处理方式。
- 执行迁移往返、完整发布检查、两账户浏览器验收和备份恢复演练。

### M5：云部署与首次多人试用

- 用户提供已购买的服务器和域名，通过安全本地配置提供凭据。
- 迁移前备份，验证云端数据库和文件恢复；仅 HTTPS 对外，数据库/API 不直接公开。
- 验证服务器重启自启和备份；另一台电脑/手机使用实际域名验证。
- 云端成为唯一正式写入环境，本机用虚构数据开发，避免两套生产数据分叉。
- 先让少量独立教师试用，根据实际困惑修复后再逐步开放。

## 首次使用者测试任务

给测试者的任务只包含目标：“注册自己的账户，保存一名虚构学生，退出并重新登录，找回刚才保存的学生；再切换到另一名教师账户。”不提供源码、接口或内部 ID。

记录：发现入口是否容易、密码规则是否提前说明、报错是否指导下一步、是否明确保存成功、退出是否成功、首次空白页能否知道下一步做什么。再进行独立的接口越权验证。

验收报告必须说明使用了真实 API 还是模拟响应、SQLite 还是 PostgreSQL、真实浏览器还是组件测试。任何层次未执行都列为待验收。

- 未修改数据库模型或运行环境配置，未调用付费 AI；未开放注册，未进行云部署。现有 3000 容器仍为上次验收版本，本阶段代码在独立预览验证，随 M2 集成部署。
- 尚需 M2/M3 验证：同时启用两位教师、真实注册、跨标签页换号、PostgreSQL 与服务器重启后持久化。
