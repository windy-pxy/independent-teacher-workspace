## 本机每次开始工作

1. 启动 Docker Desktop，等待引擎进入运行状态。
2. 在项目目录执行：

   ```powershell
   docker compose up -d
   docker compose ps
   ```

3. 确认 `db`、`api`、`web` 为 `healthy`，`worker` 为 `Up`。
4. 打开 <http://localhost:3000> 并登录。
5. AI 任务长时间停留在“等待”时执行 `docker compose logs --tail 100 worker`；不要复制公开含学生资料的日志。

电脑关闭或 Docker Desktop 停止时，本机网站无法访问；这不会删除 PostgreSQL 或文件卷。禁止执行 `docker compose down -v`。

## 首次录入顺序

先用一名学生跑完闭环，再批量录入：

1. **学科**：建立实际教授的学科。
2. **学生档案**：只录必要信息，优先使用代号。
3. **学生学科**：关联教材版本、基础与目标。
4. **教学计划**：按章节建立结构化计划与预计课时。
5. **课程与课表**：创建课程并核对日期、时长、类型和单价。
6. **资料库**：只上传当前教学确实需要的教材或试卷。
7. **AI 教案**：生成草稿后人工修改、提交审核、批准，再导出 Word。
8. **课后反馈**：输入关键词让 AI 整理，审核后才更新正式进度。
9. **错题与练习**：视觉识别结果和生成练习均先人工校正与批准。
10. **课时与收费**：确认实际分钟、收款和课程分摊。

## 日常安全规则

- `.env`、备份、上传件、Word、Excel 和 Obsidian 导出包不得提交到 GitHub。
- 不通过聊天、邮件正文或截图发送 AI、数据库、会话、SSH 或备份密钥。
- AI 生成内容必须人工审核；草稿不能直接更新正式进度或掌握度。
- 上传前删除与教学无关的姓名、电话、住址等信息。
- 退出登录只撤销会话，不删除资料；换设备后资料仍应从 PostgreSQL 读取。
- 重要记录优先归档。申请永久删除账户前先导出，撤销期过后无法从在线系统恢复。

## 备份节奏

本机快速备份：

```powershell
pnpm backup:create
pnpm backup:verify -- var/backups/<backup-id>
```

开始录入真实数据后建议每日备份。本机普通备份含完整学生资料，只能保存在受控设备。

复制到移动硬盘或异地前必须加密：

```powershell
$env:BACKUP_ENCRYPTION_PASSWORD="从密码管理器粘贴，不要发到聊天"
pnpm backup:create -- --encrypt
pnpm backup:drill -- var/backups/<backup-id>
Remove-Item Env:BACKUP_ENCRYPTION_PASSWORD
```

至少每季度执行一次恢复演练。只有清单校验和恢复演练都成功的备份才可视为可恢复。

## 本机每次结束工作

保留数据并停止应用：

```powershell
docker compose stop
```

下次执行 `docker compose up -d`。若希望关机后仍能被其他教师访问，必须完成云服务器部署，本机 Docker 无法提供这一能力。

## 云端开放前必须完成

1. 购买并配置长期在线服务器和域名；中国内地服务先完成所需备案。
2. Caddy 自动 HTTPS 可用，仅公开 80/443；数据库 5432、API 8000、Web 3000 不对公网。
3. 设置真实 `APP_DOMAIN`、`SUPPORT_CONTACT`、强随机会话/数据库密钥和 Secure Cookie。
4. 生产环境使用 `REGISTRATION_INVITE_REQUIRED=true`；先保持注册关闭。
5. 将本机数据库和文件迁移为唯一云端事实源，避免本机与云端同时录入。
6. 完成加密异地备份及恢复演练、服务器重启自启和公网探测。
7. 创建限次邀请码，让两位虚构试用教师从不同网络/设备完成注册、保存、退出重登、导出和跨账户隔离。
8. 按不了解系统的新用户记录困惑并修复复测后，再邀请真实教师。
