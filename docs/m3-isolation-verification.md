# M3 多教师隔离与持久化验收

日期：2026-09-11。所有自动测试仅使用虚构教师和虚构学生，AI 使用 Mock，未读取现有正式资料、未调用付费模型。

## 完成内容

- 浏览器写请求携带当前标签页保存的教师账户 ID，服务端与 HttpOnly 会话中的真实教师核对；不匹配返回 `ACCOUNT_CONTEXT_CHANGED`，不会执行业务写入。
- 登录、退出、密码找回和修改密码会广播登录状态变化。其他标签页收到后立即隐藏业务表单，提示确认账户并重新加载。
- 学生新增表单有未保存离开保护：关闭/刷新触发浏览器保护，站内导航先在页面中说明内容会丢失，并允许留在本页。
- 修复学生更新与归档的既有判断错位：普通编辑不再因存在计划课程而失败；归档仍会阻止有计划课程的学生被误归档。
- 新增可重复的完整双教师隔离测试和真实 PostgreSQL + Edge 验证脚本。

## 实际验证层次

### 真实 PostgreSQL 与 API

`pnpm validate:multitenant` 使用随机命名的临时 PostgreSQL 17 容器，执行：

1. `upgrade head → downgrade -1 → upgrade head → alembic check`。
2. 同时启用两名虚构教师，分别维持独立 Cookie 会话。
3. 覆盖学生、学科、学生学科关联、计划、课程、教案、反馈、掌握度入口、错题、练习、收款、提示词模板、资料、AIJob、收费 CSV 和 Obsidian ZIP。
4. 替换 URL ID、替换请求体关联 ID、跨教师下载、修改和收款分配均返回 404；旧标签页账户 ID 与新 Cookie 不一致时返回 409。
5. 越权尝试后重新读取原教师记录，确认内容和文件没有被修改。
6. 同一教师两个客户端以相同旧版本写入，后提交者收到 `VERSION_CONFLICT`，没有覆盖先提交内容。

### 真实 Edge 新手流程

- 两名虚构教师仅根据页面文字完成注册、登录、查看空状态、保存各自学生；双方页面看不到对方学生。
- 停止并重新启动真实 API 与 Next.js 服务（PostgreSQL 不停止），使用保存的浏览器会话重新访问，双方资料仍存在且隔离。
- 新增学生表单填到一半点击课程导航，页面显示未保存提醒；选择“留在本页”后输入仍保留。
- 两个独立浏览器上下文并发编辑同一学生，后提交页面显示“记录已被其他操作更新”。
- 同一浏览器上下文的另一个标签页退出并换号，旧标签页进入账户保护状态；手工模拟旧标签页提交被后端 409 拒绝，新账户没有新增错误资料。
- 页面运行异常为 0。测试状态、日志和截图仅保存在忽略目录 `var/validation/`。

## 使用边界

- 同一浏览器配置中的标签页共享登录 Cookie，因此不能同时独立操作两个账户。需要并行登录时使用不同浏览器配置、隐私窗口或另一设备；现在即使误换号，旧标签页也会被阻断。
- 未保存离开保护目前覆盖学生新增主流程和原有恢复码保存流程；后续新增复杂长表单时必须复用同类保护。
- PostgreSQL 和服务重启持久化已在临时环境验证；公网跨网络访问、云端文件恢复和服务器重启自启仍属于 M5。
- 注册默认保持关闭。M4 完成 AI 配额、账户管理、隐私和数据删除前，不开放给不受信任用户。
