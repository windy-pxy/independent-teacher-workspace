# 安全、隐私与备份

## 认证与授权

- 使用单教师账户，但所有业务表和查询仍保留教师所有权边界。
- 密码使用 `pwdlib` 推荐的 Argon2id 参数；数据库不保存明文密码。
- 会话令牌以安全随机值生成，数据库只保存 SHA-256 哈希。
- Cookie 使用 `HttpOnly`、`SameSite=Lax`；生产启用 `Secure`，写操作验证 Origin/CSRF。
- 登录、密钥设置和健康检查之外的业务页面均需认证。

## 学生数据与 AI

- 生成上下文默认使用学生代号，只选择任务所需的学情、反馈和材料片段。
- 调用前向教师展示将发送的信息类别；AIJob 只记录脱敏上下文清单和摘要。
- 不把 API 密钥、完整学生档案、无关家长信息或原始日志送入模型。
- AI 输出是草稿；教师批准前不能改变正式数据。

## 密钥与日志

- 密钥仅来自服务端环境变量，不进入 `NEXT_PUBLIC_*`、Git、数据库或日志。
- 错误响应使用请求 ID；堆栈只在受控开发终端显示。
- 审计详情采用允许字段清单，不保存完整提示词、上传正文或学生答案。

## 上传与文件

- 接口层同时校验扩展名、MIME、文件魔数和字节数。
- 对象键由服务端生成；原文件名只作为经过清理的显示元数据。
- 本地存储适配器解析绝对路径并拒绝逃逸根目录。
- 错题图片仅允许 PNG/JPEG 并校验文件魔数。资料库允许 PDF、DOCX、UTF-8 TXT，额外限制 PDF 页数/内容流和 DOCX 解压条目/总体积；文件仅解析和下载，不在服务器执行。当前单教师私有部署未集成常驻恶意软件扫描，不应上传来源不明文件；若未来开放多人或公网上传，必须先增加隔离解析与恶意文件扫描。

## 删除与恢复

- 学生、计划、课程、错题和材料默认归档；永久清除使用二次确认并记录审计。
- 付款、已批准版本和审计日志不通过普通 UI 硬删。
- Phase 6 已提供 PostgreSQL custom-format 备份、本地对象归档、SHA-256 清单、AES-256-GCM 加密和隔离恢复演练。
- 数据导出包含结构化 JSON/CSV 和对象清单，不包含密钥或会话。

## 部署要求

- 公网部署必须使用 TLS、可信反向代理、强随机密码、Secure Cookie、最小开放端口和数据库私网连接。
- Supabase service role key 只能存在 API/Worker 环境，绝不发送到浏览器。
- GitHub Actions 使用固定提交 SHA 的 Action，并且仅以最小权限读取仓库内容。
