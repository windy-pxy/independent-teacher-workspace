# Phase 4：错题与针对性练习

## 正式数据边界

- 教师手工填写完整题目、正确答案、错误原因和解析后，可直接保存为正式错题。
- 图片识别始终创建草稿版本。教师可以查看原图、核对内容、提交审核、批准或驳回；批准前不会同步知识点关联或成为出题依据。
- 每次识别、手工修订和审核均保留不可变版本或审计摘要。已批准记录在本阶段锁定，避免重复应用或静默覆盖。
- 复习记录追加保存，并更新错题自身的掌握状态、复习次数和最近复习时间；不会改写历史复习记录。
- 练习生成结果是草稿。批准事务将经过校验的题干、答案、解析、难度和知识点发布到正式题目表。

## 图片与隐私

- 仅接受 PNG/JPEG，服务端同时校验扩展名、声明 MIME、文件魔数和 `MAX_UPLOAD_BYTES`。
- 文件使用 UUID 对象键，原文件名只作为截断后的显示名，不参与路径拼接。
- 下载接口验证当前教师所有权并返回 `private, no-store` 与 `nosniff`。
- 视觉上下文使用学生实体 ID 代号和最小必要学科信息，不发送姓名、学校或家长要求。
- 默认 `VISION_AI_PROVIDER=mock`。Mock 明确标记未读取真实图片，不产生付费调用。

## AI Provider 分离

- `AI_PROVIDER` 负责教案、反馈和针对性练习的文本结构化生成，可使用 Mock、OpenAI 或 DeepSeek。
- `VISION_AI_PROVIDER` 负责图片题目识别，当前支持 Mock 和 OpenAI。业务服务只依赖统一 `AIProvider`，不直接导入厂商 SDK。
- 使用 OpenAI 视觉输入时，服务端通过 Responses API 的 `input_image` 传入 Base64 数据 URL；模型名称来自 `VISION_OPENAI_MODEL`，不硬编码。
- AI 失败只更新任务状态与脱敏错误，不改变已批准错题或正式练习。

## 当前限制

- 尚未提供批量图片、PDF 试卷切题、OCR 坐标框或重复题自动合并。
- 本阶段不把错题复习直接写入 `StudentMastery` 证据表；错题状态单独保存，后续可设计明确的证据合并规则。
- 已批准错题和练习的更正工作流将在需要时使用差异版本设计，不允许直接覆盖正式版本。
- Obsidian 仍是未来可选导出/查阅目标，PostgreSQL 是正式事实源。
